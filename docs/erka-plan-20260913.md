## 功能 1：执行结论的 Markdown 渲染

**设计**
- 新增 `content/Markdown.jsx`（约 150-200 行）：手写轻量渲染器，**不引入 DOMPurify/marked 依赖**，直接产出 React 节点（天然免疫 XSS，侧栏运行在 chrome 特权上下文，禁止 innerHTML 注入面）：标题、粗斜体、行内码、围栏代码块（横向滚动+一键复制）、表格、有序/无序列表、链接。
- `AgentPanel.jsx`：`msg__content` 中 **assistant 最终结论与阶段汇报** 走 `<Markdown>`；user 消息与工具原始输出保持纯文本（保留原样可读性）；`<details>` 折叠的思考过程用轻量版（只渲染代码块和粗体）。
- CSS：`.md-*` 类，跟随现有 Firefox 主题变量。

**验收**：让 Agent 输出一份带代码块+表格+标题的还原结论，渲染为格式化视图；复制按钮可拷贝代码块；粘贴含 HTML 标签的文本不被注入。

**工作量**：1 天。

## 功能 2：决策选项可点击 + 可补充

**设计（结构化工具协议，不靠解析文字）**
1. `Tools.sys.mjs` 新增工具 `offer_choices`：参数 `{ question, options: [{label, detail?}], allow_custom: true }`。仅「AI辅助」模式注入到工具目录；系统提示词补充：*需要用户拍板方向时调用 offer_choices，不要只用文字罗列*。
2. `AgentLoop.sys.mjs`：处理该工具时不发 LLM 往返——直接 `emit({type:"choices_offer", ...})` 并让本轮以 `stopReason:"await_choice"` 停下（复用现有 final 收尾通道，:786 附近）。
3. `ConversationStore.sys.mjs`：choices_offer 作为消息附属持久化——会话恢复/切标签页后按钮仍在，选择后置灰。
4. `AgentPanel.jsx`：渲染选项按钮组 + 「自定义补充」输入框；点击/提交 → 走现有发送通道生成 user 消息（:799 `userMsg` 路径），并把选择语义写清（如 `我选择：换路线A（补环境）`）。

**验收**：AI辅助模式跑到分叉点，面板出现可点选项；点选后 Agent 按所选方向继续；重启浏览器恢复会话仍可操作；`node dev/selftest-*.mjs` 补一条选择回路自测。

**工作量**：1.5-2 天（协议+持久化+自测）。

## 功能 3：上下文大小可设 + 自动压缩

**设计（大部分基础设施已存在，主要是"打通配置→预算→压缩触发"三处）**
1. **配置字段**：`ConfigStore.sys.mjs` 命名配置增加 `context_window`（kTokens，如 64/128/200）与可选 `max_output_tokens`；`SettingsPane.jsx` 模型配置表单加这两个输入（默认空=沿用内置探测）；`settings/agent.example.json` 同步示例。
2. **预算读取**：`AgentLoop.sys.mjs` 的 `modelBudget()` 改为：用户显式配置 > 现有模型名映射表；同时 `resultCap`/handoff 阈值按窗口等比缩放（现有 :550 逻辑不动，只换数据来源）。
3. **自动压缩**：利用已有 `Usage.sys.mjs` 逐轮累计 input tokens + `ContextProjection.sys.mjs` 的摘要机制——当预计下一轮 input ≥ 窗口×0.8 时，自动触发既有 handoff 摘要（:163 已有实现）把旧轮工具结果折叠到 `.frx-context/tool-results/`，UI 上提示「已自动压缩：省 N tokens」。
4. 兜底：若压缩后仍超限（单条巨型工具结果），沿用现有 resultCap 截断策略，并把截断标记写进投影。

**验收**：设 8k 小窗口的模型跑长任务，观察自动压缩事件、会话继续可用、UI 历史完整不丢；改 200k 后不再触发。`node dev/selftest-context-*.mjs` 补用例。

**工作量**：2-3 天（主要是回归现有 handoff 路径）。

## 功能 4：模型图片/视频能力接入

**设计（顺水推舟：管道已有，打开三处阀门）**
1. **能力声明**：模型配置加 `capabilities: {vision: true/false, video: true/false}`；provider 预设里给已知模型标注默认值（deepseek-chat 关、qwen-vl/gpt-4o/claude 开）。
2. **图片进模型**：`AgentSession.sys.mjs:57` 的剥离逻辑改为按能力分支——vision 开启时保留最近 N 张截图（默认 3，尺寸压到 ≤1568px JPEG 基内），作为 `image_url` 块随下一条 user/tool 消息发出（LlmClient 已有双协议转换，**零改动**）；关闭时维持现状。`page_screenshot`/`page_info` 返回里带图时，提示词告知模型"图已附在消息里"。
3. **视频=关键帧采样，不引入 ffmpeg**：新增页面工具 `video_snapshots`（PageBackend）：对 `<video>` 元素按时间点设 `currentTime` → canvas 抓帧 → 返回多张 base64 截图，走与图片相同的 vision 通道。模型即可"看懂"视频内容（验证码视频、教学演示等场景）。
4. 成本控制：图片进模型前压缩+计数，`Usage.sys.mjs` 的 token 统计计入视觉开销，超预算优先丢最旧帧。

**验收**：claude/qwen-vl 配置下，Agent 对含图片页面描述准确；对短视频输出分帧后的内容摘要；deepseek-chat（无 vision）下行为与现在完全一致（回归保护）。

**工作量**：2-3 天（图片 1 天，video_snapshots 1 天，调参半天）。
